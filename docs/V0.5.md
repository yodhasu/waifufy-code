# Waifufy Code V0.5 — CLI parity overhaul

Goal: a developer who knows the Claude Code CLI uses Waifufy Code with no relearning. Every interactive CLI command
has an in-app equivalent, and the app still feels like playing a visual novel. It stays built on the Agent SDK
(the real Claude Code harness); the app adds no harness of its own.

## Sources

Specs from reverse engineering the bundled `claude.exe` 2.1.309 live in `docs/research/`:

- `cli-extensions.md`: /mcp, /plugin, /skills, /hooks, /memory and the reload commands.
- `cli-settings.md`: /status, /config, /usage, /stats, /model, /effort, /fast, /permissions, /add-dir and /context.
- `cli-session.md`: /resume, rewind, /export, /tasks, /compact and the other session flows.
- `cli-input.md`: keybindings, prompt input, the spinner, the footer and dialogs, with the gap table in §6.
- `ux-research.md`: VN conventions, gamification evidence and agentic-app patterns, with P0, P1 and P2 recommendations.

## Architecture (done)

- **`ctl` / `ctl_result`** (`link/src/protocol.ts` CTL_OPS) calls the running session's controls:
  - **SDK `Query` methods:** mcpServerStatus, reconnectMcpServer, toggleMcpServer, supportedAgents, getContextUsage,
    usage, accountInfo, initializationResult, applyFlagSettings, updateSettings, rewindFiles, stopTask and others.
  - **`cli`:** runs a slash command silently and answers with its text, e.g. `/config key=value` or `/effort high`.
  - **`mcpLogin` / `mcpLogout`:** run `claude mcp login|logout`.
  - **`settingsFiles` / `editSettings`:** read the user, project and local settings files, and make atomic key edits.
  - **`cliExec`:** runs `claude plugin …`, `claude mcp list|get` or `claude agents`.
  - **`readText`:** reads text files under the project or `~/.claude`.

  App side: `control(link, op, ...args)` in `app/src/chat/control.ts`.
- **`app/src/chat/menu.ts`** draws the CLI's panel UI as a VN window:
  - grouped rows with status glyphs and meta,
  - nested screens (Esc goes back), search,
  - custom keys per screen (Space, ←/→, letters), and the CLI's footer hints.
- **`app/src/chat/commands/`** is the registry (`index.ts` APP_COMMANDS). A command with `run(host, args)` lives in its own
  file; `CommandHost` gives it the modal layer, toasts, link, cwd, the character name and `cli()`.
- **Mock session:** answers every control. Settings files are real, against a test-only `CLAUDE_CONFIG_DIR`.

## Panel contract (W2–W8)

- **Shape:** a panel is `run(host: CommandHost, args: string)` in its own file under `app/src/chat/commands/`, registered
  in `commands/index.ts`. It opens `openMenu(host, '<test-id>', screen)` and never edits `chat/index.ts`.
- **Matching the CLI:** use the CLI's titles, labels, status glyphs, footer hints and result messages from the research spec.
  Desktop-only additions are fine where a terminal concept doesn't apply.
- **Routes:** SDK through `control(host.link, op, …)`; CLI text through `host.cli('/config x=y')`; files through
  `settingsFiles` / `editSettings` / `readText`. The CLI's own `/x key=value` path is preferred whenever one exists,
  so the CLI's own save code runs.
- **Tests:** the mock (`link/src/mock.ts` mockControl, mockCli) answers what the panel needs. Each panel gets an E2E
  scenario in `tests/e2e/scenarios/` tagged with its requirement ID.

## Known gaps (headless limits, or left for later)

**Not possible headless (no SDK route):**
- The rewind options "Summarize from here / up to here".
- Foregrounding a background task, and a shell task's live output tail.
- The /permissions "Recently denied" list (classifier denials).
- Plugin, session and built-in hooks in /hooks.
- The CLI's terminal-only /config rows.
- The "s: this session only" key in the /model picker.

**Approximated:**
- **/export:** the text imitates the terminal export but isn't byte-identical.
- **/skills:** the source and lock come from command metadata, and the token count is estimated.
- **MCP tools:** the SDK reports no input schema, so the tool detail has no Parameters section.
- **/plugin favorites:** not supported.

**Left for later:**
- **Session work:**
  - multi-session tabs (P1-3);
  - Quick Save / Quick Load keys (P1-1) — rewind covers the flow;
  - Ctrl+G external editor, Ctrl+S stash, vim mode;
  - a custom statusLine command.
- **Dialogs:** the ExitPlanMode "clear context" option; the AskUserQuestion review step and notes.
- **Look:** a duplicated footer hint line on the Settings and Permissions panels.
