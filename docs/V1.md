# Waifufy Code v1: design and finish condition

**Audience:** a weeb developer who wants deep control over his own identity and how his waifu looks, talks and behaves, and who already knows Claude Code. Every Claude Code habit (Enter, Shift+Enter, ↑ history, `/`, `@`, `!`, Esc, Shift+Tab) must work unchanged. The VN layer is added on top, and nothing has to be learned again.

## Finish condition: v1 requirements

Each item must be verified working in the real app, by the E2E harness or by hand.

### Title screen (main menu)
- R1. **Continue** resumes the most recent session. It's hidden when there are no saves.
- R2. **Load** opens the Save/Load page (see below), never a list inside the menu.
- R3. **New Game** opens a folder picker, then starts a session there.
- R4. **Settings** opens the settings page. **Exit** quits; if a turn is running, it confirms first.
- R5. Keyboard: ↑↓ to choose, Enter to select, Esc to go back.

### Save/Load page (VN-style)
- R6. A grid of save slots, 8 per page, with numbered page tabs.
- R7. Each slot shows a thumbnail (captured when leaving the session or after each turn), the title, the shortened working directory and branch, the date and time, play time, turns, and affection.
- R8. Slot actions: load (resume), rename (`renameSession`), and delete. Delete only removes the save from the app's list; the transcript stays on disk. Delete asks for confirmation.
- R9. Return / Title buttons at the bottom, plus a hint bar ("Load a save and continue from there.").

### Chat: Claude Code parity
- R10. Enter sends. Shift+Enter inserts a newline (the textarea grows). ↑/↓ recall input history per project.
- R11. Typing while Rem is working queues the message. A queued chip is shown and the message goes out at the next turn, as in the CLI.
- R12. Esc interrupts the running turn. In menus, Esc closes the topmost overlay first.
- R13. Shift+Tab cycles the permission mode (default → acceptEdits → plan, plus auto if the model supports it). The badge always shows the real mode.
- R14. `/` opens the command picker: 5 visible rows, scrolling, ↑↓, Enter runs, Tab completes. It lists the SDK's commands plus app commands:
  - `/model`: picker
  - `/clear`: fresh session in the same folder
  - `/resume`: Load page
  - `/config`: Settings
  - `/costume`: costume picker
  - `/help`: help
  - `/exit`: title screen

  Commands the SDK runs itself (`/compact`, `/context`, `/cost`, skills, …) are sent through, and their output is shown.
- R15. `@` opens a file picker (fuzzy, from the session folder, respecting .gitignore) and inserts the path.
- R16. `!cmd` runs a shell command in the session folder. The output is shown, and it's added to Rem's context the same way the CLI does it.
- R17. Images: paste or drag an image into the input, or use 📎. Thumbnails appear; the images are sent as image blocks.
- R18. While Rem works: a "thinking" state with elapsed seconds and tokens (like the CLI spinner), a ribbon showing the current tool, and a live tool log.
- R19. Clicking an entry in the tool log opens a detail view: full input and full result (truncated at 20k characters, with a note).
- R20. Permission menu: shows the tool, a diff for Edit/Write/MultiEdit, the command for Bash/PowerShell, the URL for web tools. Options: Allow once / Always allow (when suggestions exist) / Deny / free-text "tell Rem instead". Destructive commands get the danger style.
- R21. `AskUserQuestion` (single choice, multi-select, Other) and plan approval (`ExitPlanMode`) work, and the answers reach the model.
- R22. The quest log follows TodoWrite and the Task* tools. The party shows running and finished subagents.
- R23. Backlog (LOG, Ctrl+L) shows the full trace: every line from you and Rem, tool calls with results, command output and errors. It can be searched and copied.
- R24. Errors (not logged in, API errors, the sidecar crashing) appear in character and in LOG, never as a silent hang. The sidecar restarts automatically.

### Dialogue (VN layer)
- R25. **The dialogue box never shows emotion tags.** Markdown is rendered readably: bold, inline code, links, short lists.
- R26. **Inline emotion timeline.** Rem writes `text [smile] text [think] text`. Each tag fires when the typewriter reaches it.
- R27. **Speaking pace.** The default typewriter speed is ~14 characters per second (about 150 wpm conversational speech), with pauses at `,` `;` (~180 ms) and `.` `!` `?` `…` (~420 ms). Text speed can be set from speech pace up to instant. Clicking finishes the current page; holding Ctrl skips.
- R28. **Lip sync.** Her mouth (`ParamMouthOpenY`) moves while the typewriter is printing letters and closes during pauses.
- R29. **Long output is collapsed.** Code blocks, tables, lists longer than 4 items and paragraphs longer than ~320 characters become one short page ending in `…`, plus a "(full text in LOG)" hint. The full text is always in LOG.
- R30. Pages: one paragraph per page (long prose is split at sentence boundaries). ▼ shows that more is coming, with a count. AUTO advances by itself.

### Live2D: alive and interactive
- R31. **Idle life.** Breathing and blinking from the engine. Every 8–20 s an idle variation plays (normal02, normal03, or a small smile), never while she is speaking.
- R32. **Cursor tracking.** Her head and eyes follow the cursor anywhere in the window, scaled by distance (as in waifufy), with the stage's CSS scale handled correctly.
- R33. **Headpats.** Press and drag across her head. This is ported from waifufy, without voices: tiers escalate from happy, to shy, to "stop slacking off" pout, to sulking. While Rem is working, she scolds you instead.
- R34. **Taps.** Clicking her face gives surprised and then pout; clicking her body gives a shy reaction. Tapping repeatedly escalates.
- R35. **Event gestures.** Permission requests (worried or thinking), destructive commands (surprised, serious), a successful `git push` (nod, delighted), a finished long turn (happy), and errors (sad) each play a gesture. While working she holds a thinking or serious pose between lines.
- R36. **Costumes.** A 👗 button in the chat opens a costume picker with all Rem costumes found in the models folder. Switching swaps the model live and keeps the current emotion. Motions are matched by suffix with fallbacks, because each costume has a different motion set. The choice is remembered.
- R37. If no model is found, a built-in placeholder sprite is shown and the chat still works fully.

### Settings (deep customization)
- R38. **You (profile):**
  - display name
  - what she calls you
  - honorific (-kun / -sama / -chan / -san / -senpai / -dono / none / custom)
  - pronouns
  - avatar image
  - title or role
  - "about me" (free text she should know)
  - nameplate color
- R39. **Waifu:**
  - character name (default Rem) and series
  - relationship dynamic (maid & master, childhood friend, senpai/kouhai, partner, rival, custom)
  - personality (presets plus free text)
  - speech style: formality, playfulness and verbosity sliders, catchphrases, Japanese words/honorifics toggle, kaomoji toggle
  - how in character the work output is (Full / Balanced / Work mode)
  - emotion expressiveness (how many tags per paragraph)
  - custom instructions
  - a live preview of the generated persona prompt
- R40. **Roleplay research (auto-research).** Enter a character name, series and optional notes, then press **Research**. A cheap model (Haiku 5.5, with web search and fetch) researches the character and returns a structured profile and a tailored roleplay prompt:
  - personality
  - speech patterns
  - catchphrases
  - how they address people
  - relationship cues
  - do/don't rules
  - sample lines

  Progress is shown. The result is a preview the user can edit, then **Apply** fills in the Waifu tab. Several research results can be saved as persona presets and switched between.
- R41. **Appearance:**
  - theme: Light / Dark / System
  - accent color
  - dialogue font size
  - dialogue box opacity
  - background (day / night / sakura petals on-off)
  - costume
  - sprite zoom
  - models folder path (default: your Downloads costume folder, then waifufy's assets)
- R42. **Text & motion:**
  - text speed
  - punctuation pauses
  - auto-advance delay
  - lip sync on/off
  - idle motions on/off
  - cursor tracking on/off
  - headpats on/off
  - tap reactions on/off
  - event gestures on/off
- R43. **Claude:** default model, default permission mode, default folder for New Game, and which settings sources to load (user/project/local).
- R44. **Voice:** "Off". An "AI voice provider: coming soon" placeholder with a disabled selector. No audio plays in v1.
- R45. Every setting applies live where it can (theme, text speed, costume, toggles) and persists to `%APPDATA%\waifufy-code\settings.json`. Persona changes apply to the next session, and Settings says so.
- R46. **Dark mode** themes every screen: menu, saves, settings, chat panels, dialogue, overlays and the backdrop (a night scene).

### Packaging
- R47. `npm run build:installer` produces an NSIS `setup.exe` that bundles the Node runtime, the link sidecar with its production node_modules (including the Claude Code binary from the SDK), and the frontend. No repo checkout or global Node is needed.
- R48. First run: a welcome wizard detects the models folder (asking for it if missing), checks the Claude login (showing a "Log in" action that opens the bundled Claude Code login when not logged in), and sets up your profile.
- R49. Dev mode (`npm run dev` at the repo root) still works.

## Architecture

```
app (Tauri 2, WebView2)                         link (Node sidecar)
 main.ts ─ router: title | saves | settings | chat   server.ts  HTTP + WS (token)
 character/ ─ Live2D: load, resolve motions,          session.ts Agent SDK query(), tags, asks, stats
              interactions, lipsync, costumes          settings.ts schema + defaults + persistence
 chat/ ─ dialogue (pages, timeline, typewriter),      persona.ts settings → system prompt append
         input (history, slash, @, !, images),        research.ts Haiku + web tools → persona preset
         panels (stats, quests, party, actions),      saves.ts  registry, rename, delete, thumbnails
         asks (permission, question, plan)            files.ts  @-mention file index
 screens/ ─ title, saves, settings, wizard            shell.ts  ! commands
 theme.css tokens (light/dark)                        assets.ts models (multi-root), costume list
```

```ts
// app/src/chat/input.ts
export type InputHost = {
  ctx: Ctx
  /** Slash commands from the SDK (`ready`/`commands` events). */
  commands(): Command[]
  /** Session folder, for the per-project history key and @ search. */
  cwd(): string
  busy(): boolean
  /** A normal message (may contain @paths; the CLI expands them). */
  submit(text: string, images: Image[]): void
  /** `!cmd` */
  shell(command: string): void
  /** App-native commands: model, clear, resume, config, costume, help, exit. Return true if handled. */
  local(name: string, args: string): boolean
  /** Enter on an empty input: advance the dialogue. */
  advance(): void
}
export type InputApi = {
  focus(): void
  /** Queued messages shown as chips above the input; clicking a chip's × removes it (host.dequeue). */
  setQueued(items: { id: string; text: string }[], onRemove: (id: string) => void): void
  setEnabled(on: boolean, placeholder?: string): void
  /** Puts text back into the input (Esc restores queued messages, as in the CLI). */
  restore(text: string): void
  /** True while the slash / @ picker is open; Esc closes it first. */
  closePopups(): boolean
}
```

Shared conventions:
- `Ctx.link.send({t:'files', query})` → `{t:'files', query, hits}`. The input matches replies by `query`.
- Character interactions use pointer events on `#chara`. Only the character's own canvas area captures pointer events (`#chara canvas { pointer-events: auto }`), and UI panels sit above it in z-order. Cursor tracking listens on `window`.
- Z-order inside a screen: character layer `#chara` (z 1) < screen content (z 2+) < overlays (z 50) < toast (z 90).
- `.screen` roots are `pointer-events: none` and their direct children are `auto`. A screen that wraps everything in one full-size child blocks the character, so give full-stage pages (saves, settings) their own backdrop. On the title and chat screens, keep the area around the character free of full-size wrappers.
- Stage coordinates: everything is laid out in 1600×900 stage pixels. `#stage[data-scale]` holds the CSS scale for converting `clientX/Y`.

Rules:
- `link/src/protocol.ts` is the only contract between the two halves. The app imports it for types only.
- Each module owns its own CSS file. Colors come only from the tokens in `app/src/theme.css`, never as raw colors elsewhere, so dark mode covers everything.
- Screens build their own DOM from TypeScript templates. `index.html` holds only the shell.
