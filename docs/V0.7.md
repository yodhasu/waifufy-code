# Waifufy Code 0.7: work and casual

Claude Code is tuned for work, so Rem talking through it always sounds like a coding agent in a costume. 0.7 adds a casual mode with its own small harness, built for talking, on the same session and the same history. Everything lives in `link/src/casual/`.

## Modes on one session

`modes.ts` wraps every session (the real one in `session.ts` and the E2E mock) in a `ModalSession`. Work mode passes straight through to Claude Code. Casual mode sends messages to `engine.ts`. Slash commands always go to Claude Code, and `/casual` and `/work` switch.

- **Shared history.** Every casual exchange goes into the Claude Code transcript as a `<waifufy-casual>` block (`block.ts`), appended with `shouldQuery: false`, so no turn runs. The work persona knows these blocks are casual chat, and `saves.ts` turns them back into backlog lines tagged `mode: 'casual'`. Casual mode sees the same history from a pool the wrapper keeps: work lines tagged `[work]`, and work actions as one line each. The pool is seeded from the transcript when a save is resumed.
- **No switching while work runs.** A turn, a running background task or a running helper agent blocks the switch to casual. She refuses with a prebuilt line (face, Japanese voice line, text) instead of a model call. The third try within 10 minutes costs one affection point.
- **Offers.** Casual replies carry `work=1` in their appraisal when you ask for real work: the app offers to switch and send the message there. Work replies may end with `[casual?]` for plain chat.

## The casual turn (`engine.ts`, `prompt.ts`)

- **System prompt:** her character card (shared with the work persona through `persona.ts`), chat rules, the appraisal line, emotion tags, three tools, the voice section, and the tunable style. It changes only when settings or learning change, so providers cache it.
- **History window:** clipped lines, cut back from 14k to 8k characters only when it overflows, so its start (and the cached prefix) stays put for many turns.
- **Per-turn note** on the newest message (`<waifufy-context>`): the time, how long since your last message, affection, how she feels, and the memories that match.
- **Reply:** streamed through the work-mode `TagParser` (faces, `<ja>` voice lines, affection tags) after `FeelParser` takes out the hidden `<feel joy=… sadness=… anger=… surprise=… fear=… sure=… work=…/>` appraisal.
- **Tools:** `use_tools` is a one-off Claude Code run (`toolModel`, default haiku) with your settings, tools and MCP servers. It can't edit, web and file reads are pre-approved, and anything else asks through the normal permission prompt. `remember` and `recall` work on memory.

Measured on gpt-6-luna with reasoning off: about 1.8–2k input tokens per turn, 80–90% of them cached after the first, and 40–90 output tokens.

## Providers (`providers.ts`)

- **OpenAI-compatible** `/chat/completions` with streaming and function calling, when `casual.provider` is `openai` and a key is stored (`casual-api.key` in the data folder; `WC_CASUAL_KEY` overrides it).
- **Claude otherwise,** through the Agent SDK with a custom system prompt, no settings, no built-in tools, thinking off and nothing saved. History goes in as stable text blocks, so caching still works. If the OpenAI call fails before any text, Claude answers instead.
- In mock mode a scripted provider answers, unless `WC_REAL_CASUAL=1`.

## Heart (`heart.ts`)

- **Five feelings:** joy, sadness, anger, surprise and fear, each 0–1 and independent.
- **Traits per personality preset:** baseline, sensitivity, half-lives, inertia, mask and clinginess.
- **What moves her:**
  - **Appraisals:** a model appraisal moves her through `feel()`. Pushes saturate, and low affection makes unkindness land harder and kindness softer.
  - **Time:** `settle()` decays every feeling back to baseline, and negative feelings recover faster when she's close to you.
  - **Being away:** `reunion()` adds the feeling of you coming back after 6 hours or more.
  - **Work mode:** affection tags at work feed her heart too.
- **What she shows:** the mood comes from the feelings in code (`moodOf`). It's never shown; it sets a tone guide for the model, her resting face, the voice speed and a tone-only note in work mode. Saved per character in `heart/<name>.json`.

## Memory and learning (`memory.ts`, `learn.ts`)

Per character, in `memory/<name>/`:

- `facts.json`
- `episodes.json`
- `notes.json`: what works and what to avoid
- `tune.json`: the only editable part of her prompt, with revisions in `tune-history.jsonl`
- `journal.jsonl`: casual exchanges waiting to be learned from
- `judge-log.jsonl`

Lookup is local BM25, so it costs nothing.

After `idleMin` quiet minutes, or about a minute after the link starts with a backlog, `learn()` runs:

1. **Reflect and judge, in one call:** facts, an episode in her voice, what works or doesn't (judged from how you reacted), and a 0–10 score on character, natural, length, memory and attunement.
2. **Critique, only below `judgeThreshold`:** a critic rewrites only the style and examples. Examples keep only tags the app can play.
3. **Replay:** the last three real messages are answered with the new style, and a judge compares the replies blind. The revision is kept only if it wins most of them.

## Requirements

- **R79:** a Work / Casual switch in the composer moves the running session between Claude Code and the casual harness. Casual mode has its own placeholder and no permission chip, and her replies come from the casual engine with nothing hidden leaking.
- **R80:** a work request in casual mode offers work mode, and accepting sends the message there.
- **R81:** while work runs (a turn, a background task or a helper agent), the switch is refused in character with a prebuilt line. The third try within 10 minutes costs an affection point.
- **R82:** running background tasks show as a chip in the party that opens /tasks.
