# Waifufy Code 0.8.2: her in 3D on the phone

0.8.1's 3D cards didn't load on the Android app: it fell back to the Live2D costume. 0.8.2 sends the phone a lighter model and, should it still fail, says why, on the phone and in the desktop's log.

## Why it failed

MMD models ship big textures. Reine's are 70 MB of TGA, six of them 4096×4096: decoded, that is about 400–500 MB of GPU memory before mipmaps. A desktop GPU holds it; a phone's WebView can't give one page that much, so the model never came up (or the WebGL context was lost). The test browser, with a desktop's memory behind it, loaded it fine, which is why the 0.8.1 phone tests passed.

## What changed

- **Smaller textures for the phone** (`link/src/tga.ts`, `assets.ts`). Requests that come in on the phone listener get each TGA texture scaled to at most 1024 pixels (a 2×2 box filter, halving until it fits), re-encoded as run-length TGA, so the file names and the loader stay the same. The scaled copies are cached in the data folder (`mmd-small/`, keyed by the file, its size and its time) and shared by parallel requests. Reine's textures go from 68 MB to 12 MB, and her GPU footprint from ~450 MB to about 46 MB (about 60 MB with mipmaps); converting the biggest takes ~0.3 s once. The desktop keeps the full textures.
- **Lighter drawing on the phone** (`mmd.ts`): no self-shadows (a second render of her every frame), no antialiasing, and at most 1.5× pixel density.
- **If the GPU drops her** (a lost WebGL context), she goes back to her Live2D costume for the rest of the run instead of leaving the stage empty.
- **Failures are visible.** A 3D model that can't load, or whose context is lost, shows a toast on the device, and the error, with the device's browser string, goes to the desktop's `link.log` (`[page · phone] …`), the only place a phone's errors can be read without a cable. New message: `client_log`.

## Tests

- `tests/unit/tga.test.mjs`: both row orders, the RLE round trip, the 2×2 average, and files it should leave alone.
- `tests/e2e/scenarios/30-mmd.mjs`: a phone gets the biggest texture at most 1024 pixels on a side.
- **The tests no longer need the installed app closed.** The link's phone port can be moved (`WC_REMOTE_PORT`); the E2E launches and the `continuity` and `remote` unit tests use their own, so they run beside an installed app holding 47920.

Not verified on a real phone: no Android device or emulator was available while this was made. The phone path was checked in the test harness's phone, and the memory estimate is from the textures' sizes.
